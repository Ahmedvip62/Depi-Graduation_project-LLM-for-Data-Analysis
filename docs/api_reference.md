# API Reference

The Universal Analyst backend is a FastAPI app. All backend routes are served at root on `http://localhost:8000`; there is no `/api` prefix on the backend itself.

The `/api` prefix only exists in front of the frontend. Vite, nginx, and the notebook proxy map `/api/...` to backend root routes while stripping `/api`.

- Direct backend: `http://localhost:8000/upload`
- Via frontend proxy: `/api/upload`

## `GET /health`

Liveness check.

Returns:

```json
{
  "status": "ok",
  "service": "universal-analyst-backend",
  "environment": "development"
}
```

## `POST /upload`

Ingests, profiles, chunks, and embeds a dataset, then creates a session. Upload-time EDA returns metadata and suggested questions only; static upload-time charts are intentionally disabled so visuals are generated by the LLM chat path.

Accepts `multipart/form-data` with key `file` for `.csv`, `.json`, `.parquet`, `.pdf`, `.sqlite`, or `.db` files. Max size: 200MB.

Returns:

```json
{
  "session_id": "uuid-v4-string",
  "profile": {
    "file_name": "sales_data.csv",
    "row_count": 500,
    "column_count": 8,
    "numeric_columns": ["sales", "quantity"],
    "categorical_columns": ["product", "region"],
    "datetime_columns": ["date"],
    "missing_pct": 0.0
  },
  "eda": {
    "summary": {
      "row_count": 500,
      "column_count": 8,
      "missing_pct": 0.0,
      "memory_human": "40.0 KB",
      "numeric_count": 2,
      "categorical_count": 2,
      "datetime_count": 1
    },
    "charts": [],
    "suggestions": ["Generate a dashboard for this dataset."]
  }
}
```

## `POST /chat`

Runs the skill loop against a session and streams model output. Dashboard and chart requests use a separate strict model chart-plan pass; the backend validates that plan and renders Plotly artifacts. If the chart plan cannot be validated, the backend asks the model to repair the plan and returns a real error if it still cannot render. No static dashboard charts are substituted. Report requests select the `report` skill and emit `download_report` so the frontend can download the current session PDF.

Accepts:

```json
{
  "session_id": "uuid-v4-string",
  "message": "Generate a dashboard for this dataset",
  "enable_thinking": false,
  "attachments": []
}
```

Optional image attachments are supported for multimodal turns:

```json
{
  "type": "image",
  "mime_type": "image/png",
  "name": "chart.png",
  "size": 12345,
  "data": "base64-without-data-url-prefix"
}
```

Supported image MIME types: `image/png`, `image/jpeg`, and `image/webp`.

Returns `text/event-stream` with these events:

| Event | Meaning |
|-------|---------|
| `skill` | Selected skill metadata |
| `command` | UI command such as `show_dashboard` or `download_report`; includes `session_id` so stale streams can be ignored |
| `action` | Current backend phase |
| `thinking` | Reasoning tokens when thinking mode is enabled |
| `token` | Streamed assistant text |
| `chart` | Generated Plotly figure spec from a validated model chart plan; includes chart `id`, `source`, `session_id`, and optional `description` |
| `usage` | Ollama token metadata when available |
| `error` | Real backend/model/chart error |
| `done` | Stream finished |

Example command event payloads:

```json
{"command": "show_dashboard", "session_id": "uuid-v4-string"}
```

```json
{"command": "download_report", "session_id": "uuid-v4-string"}
```

## `POST /visualize`

Builds one Plotly chart from a declarative chart spec. This endpoint is retained for API compatibility; chat dashboard generation uses the same validated declarative spec shape produced by the model chart-plan pass.

```json
{
  "session_id": "uuid-v4-string",
  "chart_spec": {
    "type": "bar",
    "x": "product",
    "y": "sales",
    "color": null,
    "aggregate": "sum",
    "top_n": 10,
    "sort": "desc",
    "title": "Sales by Product"
  }
}
```

Returns:

```json
{"chart": "<plotly figure JSON string>"}
```

## Sessions

- `GET /sessions`: list active sessions with dataset metadata, message counts, and generated chart counts.
- `POST /sessions`: create an empty session.
- `GET /sessions/{session_id}`: get metadata, chat history, and persisted generated chart artifacts.
- `DELETE /sessions/{session_id}`: delete a session.

## Skills

`GET /skills` returns the active skill manifest.

```json
{
  "skills": [
    {"id": "general_qa", "kind": "llm_prompt_skill"},
    {"id": "analysis_with_visual", "kind": "llm_prompt_skill"},
    {"id": "visualization", "kind": "llm_visual_plan_skill"},
    {"id": "report", "kind": "llm_narrative_export_skill"}
  ]
}
```

## `POST /skills/report`

Generates a professional PDF report for the session. `session_id` is a query parameter. The model writes a grounded narrative (executive summary, key findings, per-chart readings, data-quality note, recommendations) via Ollama structured output; ReportLab renders that narrative alongside dataset KPIs, data-quality signals, strongest profile correlations, a column dictionary, stored model-generated Plotly charts, and recent transcript excerpts. If the model is unavailable, the deterministic profile/chart/transcript sections render on their own. An optional JSON body may carry generated Plotly chart specs to embed; otherwise charts stored on the session from prior chat turns are used.

`POST /skills/report?session_id=<uuid>`

Returns `application/pdf`.
